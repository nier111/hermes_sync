# CLI 学习会话抽取与复用

## 适用场景

从 ChatGPT 数据导出中找回数学、信号与系统、DSP 等长辅导会话，并在不支持 LaTeX 渲染的 CLI/终端里继续使用。

## 分支抽取

- 全库取证或统计：可遍历整个 `mapping`，但必须知道其中可能同时包含编辑分叉、废弃回答和推理节点。
- 生成可续聊阅读稿：从会话 `current_node` 开始，沿每个节点的 `parent` 回溯至根，再反转列表。
- 仅保留 `author.role` 为 `user`/`assistant` 且 `content_type == text` 的消息；跳过 reasoning recap、thoughts 和空节点。
- 每条消息记录时间与 `message.metadata.model_slug`；不要用顶层 `default_model_slug` 代替逐条模型归属。
- 验证主分支节点数、用户文本数、助手文本数和输出字节数。用户/助手数不必严格相等，因为客户端可能保存连续助手节点。

## 终端公式排版

原始 Markdown 档案保持不变；回答用户时做显示层转换：

```text
X(z)
= Σ[n=0→∞] a^n · z^(-n)
= Σ[n=0→∞] [a·z^(-1)]^n

令 r = a·z^(-1)
收敛条件：|r| < 1
因此：|z| > |a|
```

规范：

- 默认纯文本、Unicode 与 ASCII 代码块，不把 `\\frac`、`\\begin{aligned}` 等 LaTeX 源码直接作为主要展示。
- 幂写成 `z^(-1)`；求和写成 `Σ[n=0→N-1]`；积分写成 `∫[-∞→+∞]`。
- 复杂分式用纵向 ASCII 排版，矩阵与分段函数用等宽代码块对齐。
- 复杂表达式若用户需要复制到支持 LaTeX 的编辑器，可在可读版之后附一行 LaTeX 源码；可读版优先。
- 不要修改归档原文来迎合终端，否则会损失一手证据；只转换新生成的讲解。

## 教学内容复用

抽样时优先选“用户具体卡点 → 助手回答 → 用户追问/纠正”的连续回合，而不是只读孤立高分答案。评价旧回答时分别检查：

1. 是否准确定位卡点；
2. 是否从定义推导；
3. 是否存在约定依赖却说成绝对结论；
4. 是否公式正确但因果解释不严谨；
5. 是否重复总结、模板化夸奖或强制出题过多。

复用目标是继承有效的解释路径，而不是机械复刻客户端措辞。
