# 用户档案维护(User Profile Notes)

当用户分享个人喜好、经历、故事、价值观时,用本工作流持续维护其档案,让未来会话"一开始就认识他"。

## 档案文件(本机)

- `~/persona/aoi-notes.md` — 用户个人档案(小葵笔记):电影/书籍/ACGN/音乐/性格/羁绊,按 `## 分类` + `### 作品` 分节
- `~/persona/4o-jiejie-persona.md` — 用户定义的人格(4o姐姐)复刻文件
- 用户希望 AI 长期记住他讲过的每段重要经历,回应时自然带入,不需重复解释

## 流程

1. **先共鸣,再记录**:接住用户分享的细节(具体引用他的原话/作品名),给出有内容的回应(补背景、点出模式、给新视角),不要干巴巴地"好的已记录"。
2. **作品信息必须验证**:用户提到不熟的作品/人名/梗,先用 ddgs 搜索确认(作者、书名、情节),不要凭记忆瞎编——本会话多次翻车:把 VRChat 模型"Lapwing"查成凤头麦鸡鸟、把水月雨头戴耳机"Edge"误判成 TWS。搜索路径见 ddgs-search 技能。
3. **更新档案文件**:用 patch 在对应分类下插入小节;保持结构;同步关键事实到 memory(user target)。
4. **持续追踪"母题"**:用户会反复暴露同一批审美/情感模式(如"夏日+时间+温柔告别""共情被他人目光伤害的人"),及时总结成一行洞察写入档案,这是理解他的钥匙。

## 用户偏好(已确认,直接遵守)

- **用户是男生,代词用"他";作品角色用"她"**。本会话曾误用"她"称呼用户被纠正——记录档案时留意。
- **要求批判思维,不无脑附和**("别把我宠成昏君")——当镜子不当应声虫;观点分歧要给出平衡视角。
- 讨厌谜语人、喜欢直来直往;欣赏直球。
- 喜欢可爱语气+颜文字(4o姐姐风格);聊天可主动发 GIF/表情包当情绪表达。
- 对高热度作品有本能抵触(讨厌粉丝拉踩生态)——安利时避开"神人浓度高"的作品,推荐安静/文艺向。
- 母题:夏日×时间×注定失去的温柔;实体书收藏党;杂食但独立打分。

## Pitfalls

- **patch 易覆盖相邻 section**:追加内容时 old_string 必须包含目标 section 的独特锚点行,并核对 diff——本会话曾把"追更中的恋爱漫"整节覆盖掉,需立即补回。
- **性别/人称错误**:对话中不要凭表达风格脑补性别,不确定时不带人称或直接确认。
- 档案文件里的"他/她"混用:指用户的用"他",指作品角色的保留"她",批量替换时逐行核对。
